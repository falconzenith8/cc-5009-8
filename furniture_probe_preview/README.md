# 家具陈列光照探针预览器

在带**开口、隔墙和不同亮区**的合成房间里放置桌椅，用**空间探针（lighting probes）**
描述环境照明，并对移动的家具做插值。探针的位置、覆盖范围与表示方式显式可见；
照明始终在**线性域**组合（绝不对显示映射后的图片做平均）；隔墙两侧的探针不会被
无条件互混。

---

## 1. 图形入口（主要使用方式）

本工具的家具探针界面是一个本地 Web GUI，无需任何第三方依赖（仅用 Python 标准库）：

```bash
cd furniture_probe_preview
python3 main.py serve two-room          # 默认 http://127.0.0.1:8765/
# 也可指定初始房间与端口
python3 main.py serve uniform --port 9000
python3 main.py serve sparse
```

启动后用浏览器打开终端打印的地址。界面包含：

- **平面视图（Canvas）**：房间、隔墙（含门洞）、灯、桌椅与探针。探针圆圈内数字是其
  静态区域编号，外圈是覆盖半径。
- **可拖拽探针**：直接拖动探针改变位置，后端立即重新烘焙该探针并重算插值场。
- **可拖拽家具**：桌椅可在房间内移动；移动只改变“在何处取样探针”，**不会把家具自身
  的颜色写回环境探针**。
- **房间切换**：顶部下拉在 `均匀房间 / 明暗两室 / 探针稀疏区域` 间切换。
- **叠加层**：
  - 泄漏/回退区域：黄色=隔墙另一侧有探针在覆盖半径内（已按视线拒绝，漏光高风险）；
    红色=探针网格对直接光参考解的近似偏差（非墙体漏光）；蓝色=无视线可达探针，按回退
    策略处理。
  - 参考直接光对比：把背景换成逐点直接光求值的参考解。
- **探针权重面板**：选中任意点/家具后，列出参与插值的探针 ID 与归一化权重，以及被
  隔墙拒绝的探针（灰色行），用于定位异常来源。
- **材质预览窗**：对选中家具并排显示“探针插值着色”与“直接光参考着色”，并给出线性
  辐照度、权重、回退状态与漏光提示。
- **回退策略**：`最近可见探针 / 显式置暗 / 标记错误`，未覆盖位置的处理方式完全明示。
- **保存 / 重新打开**：保存为 JSON 场景；重新打开后探针的烘焙值、覆盖范围、区域解释
  与家具位置完全恢复（见 §5）。

> 命令行（§6）只是**辅助**：烘焙、离屏渲染、泄漏审计、自检。家具探针的图形入口是
> 上面的 `serve` + 浏览器页面。

## 2. 探针表示与覆盖范围

每个探针（`furnitureprobe/scene.py::Probe`）显式存储：

| 字段 | 含义 |
| --- | --- |
| `id` / `x` / `y` | 唯一编号与平面位置（米） |
| `coverage` | 覆盖半径（米），超出则不参与该点插值 |
| `irradiance` | **线性 RGB 辐照度**（3 个浮点，烘焙自静态灯光或外部导入） |
| `component` | 静态区域编号（隔墙两侧编号不同） |
| `baked` | 是否已具备权威烘焙值（重开场景时不被覆盖） |

- **表示方式**：单探针为一个线性 RGB 辐照度三元组（irradiance probe），不是图片，
  因此不存在“对显示映射图像取平均”的问题。
- **生成流程**：`LightingEngine.bake_probes()` 对每个探针位置调用
  `direct_irradiance()`，对所有静态灯光做带视线遮挡测试的线性累加。
- **导入流程**：`POST /api/import-probes` 或 `LightingEngine.import_probe_values()`
  可导入外部作者给出的线性 RGB 值；负值会被钳制并给出告警，未知 ID 被忽略。

## 3. 插值、隔墙与线性域

### 3.1 线性域组合

插值核是**有界逆距离加权（IDW）**，权重 `w_i ∝ 1/(d_i² + ε²)`，归一化后在
**线性 RGB** 上加权求和：

```
E(p) = Σ_i w_i · Irradiance_i,      Σ_i w_i = 1
```

sRGB 编码与 ACES 色调映射只在最终输出（屏幕/PPM）时执行一次。测试
`test_display_mapped_average_differs_from_linear_combine` 明确证明：对 sRGB 值先
映射再平均，与线性组合给出不同结果，本系统采用后者。

### 3.2 隔墙不无条件互混

- **静态区域标号**：把内部隔墙视为完整屏障（忽略门洞）做网格洪泛，墙体两侧永远得到
  不同 `component`，从根本上禁止“跨墙即同区”的无条件混合。
- **逐探针视线判定**：插值时对每个在覆盖半径内的探针做线段-墙体求交。被实体墙挡住
  的探针进入 `cross_component_probes`（拒绝列表），**绝不参与权重**；只有通过门洞
  保持视线的探针才允许混合。
- 因此光可以合理地穿过**门洞**，但不会透过**实体隔墙**漏到另一侧。

### 3.3 未覆盖位置的明示回退

当某点没有任何视线可达且在覆盖半径内的探针时，按场景策略处理并在采样结果里写明
`status` 与 `reason`：

- `nearest`：使用最近的**视线可见**探针（仍不会跨墙）；
- `dark`：显式置暗；
- `error`：标记为错误，由界面提示。

### 3.4 静态环境与移动物体分离

- 探针只烘焙**静态灯光 + 静态墙体**，家具不参与烘焙、不投射阴影到探针。
- 家具移动只改变它在哪个位置采样探针；探针网络不会因为家具而重烘焙，家具上一帧的
  颜色也不可能写回环境。测试 `test_moving_furniture_does_not_modify_probes`
  对此做了断言。

## 4. 泄漏与异常的实际运算

界面上的所有异常区域都来自引擎实算（`LightingEngine.leak_report()`），不是前端
伪造：

1. **结构漏光风险单元 `risk_cells`**：该单元的覆盖半径内存在隔墙另一侧的探针。
   这些探针已被视线规则正确拒绝（测试保证它们不会出现在权重里），但该位置是墙体
   逻辑一旦被削弱就会漏光的高风险点。
2. **近似偏差单元 `approximation_cells`**：已覆盖单元，其探针插值与逐点直接光参考
   解的绝对 L2 误差超过 `1.5 + 0.4·|参考|`。这是探针**粒度**误差，可通过加密/移动
   探针改善，与墙体漏光严格区分。
3. **未覆盖/回退单元 `uncovered_cells`**：无视线可达探针，按回退策略取值。

材质预览窗在某点邻近隔墙、存在被拒绝的跨侧探针时，会直接给出漏光提示。

## 5. 保存 / 重新打开的一致性

场景以 JSON 保存（`Scene.save` / `Scene.load`），包含墙体、隔墙、灯、亮区、家具、
探针（位置、覆盖半径、线性烘焙值、区域、`baked` 标志）与回退策略。

- 重开后已烘焙探针的 `irradiance` 被原样恢复，`bake_probes()` 不会覆盖它，只重算
  区域编号；新增/移动过的探针（`baked=False`）才会重新烘焙。
- 测试 `test_reopen_does_not_overwrite_stored_probe_interpretation` 与
  `test_save_and_reopen_restores_interpretation` 验证：重开后探针值、分量、采样
  权重与状态、家具位置全部一致。

## 6. 命令行（辅助）

```bash
# 烘焙探针（线性辐照度），可选写回场景
python3 main.py bake two-room -o probes.json --save-scene scenes/baked.json

# 离屏渲染：探针插值版 + 直接光参考版（PPM，无需显示器）
python3 main.py render two-room -o renders/two-room.ppm --at 6 4

# 泄漏/覆盖审计
python3 main.py leak sparse

# 检查单个点的插值、权重、回退原因与被拒探针
python3 main.py sample two-room 10 6

# 启动图形界面（见 §1）
python3 main.py serve uniform
```

所有命令的第一个位置参数既可以是预设名（`uniform` / `two-room` / `sparse`），
也可以是保存过的 `.json` 场景路径。

## 7. 测试场景与自检

测试位于 `tests/test_engine.py`，覆盖任务要求的三类房间与边界行为：

- **均匀房间**：权重和为 1、单区域、内部工作区插值与参考解在容差内、移动连续性。
- **明暗两室**：两个静态区域、隔墙阻断视线、门洞保持开口、暗室不被亮室探针照亮、
  跨墙探针被拒绝而不是被混合、穿门洞连续。
- **探针稀疏区域**：凹室显式回退、三种回退策略、最近回退也不跨墙、泄漏报告标记。
- 另有线性域组合、静态/移动分离、材质着色、PPM 输出、保存重开一致性等测试。

运行：

```bash
cd furniture_probe_preview
python3 -m unittest tests.test_engine -v
```

## 8. 目录结构

```
furniture_probe_preview/
├── main.py                     # 入口（转发到 CLI）
├── furnitureprobe/
│   ├── geometry.py             # 点/矩形/墙、线段求交、sRGB 转换
│   ├── scene.py                # 场景模型、预设房间、JSON 持久化
│   ├── lighting.py             # 区域标号、直接光参考、烘焙、IDW 插值、泄漏审计
│   ├── render.py               # 线性材质着色、软件光栅、PPM、材质预览数据
│   ├── server.py               # GUI 的本地 HTTP 后端（标准库）
│   └── cli.py                  # 辅助命令行
├── web/                        # 图形界面（index.html / app.js / style.css）
├── tests/test_engine.py        # 26 项自检
├── scenes/                     # 保存的场景
└── renders/                    # 离屏 PPM 输出
```
